# Changelog

Все заметные изменения ProtoGrid. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — [Semantic Versioning](https://semver.org/lang/ru/).

Ветка `dev` — разработка, `main` — только релизы. Запись попадает сюда в момент
выпуска, порядок действий — в [docs/releasing.md](docs/releasing.md).

## [0.3.0] — 2026-11-27

### Добавлено

- **ProtoGrid-core Lite** — второй вариант ProtoGrid-core, отдельная сборка форка
  только для VLESS/Reality по TCP. Сохранены TUN, mixed-вход, direct/block/selector
  и Clash API, поэтому работают и VPN-режим, и системный прокси; остальные протоколы
  и транспорты в бинарник не попадают. В настройках у пункта ProtoGrid появился
  переключатель «Обычный / Lite». Собирается вместе с полным ядром
  (`scripts/build-fork.sh`), лежит рядом с приложением (`protogrid-core-lite.exe`).
- **Android Lite** — вместе с обычным APK теперь собирается и публикуется
  `ProtoGrid-<версия>-lite-arm64-v8a.apk` с лёгким ядром. У Lite-сборки
  отдельный `applicationId` (`app.protogrid.client.lite`) и название
  «ProtoGrid Lite», поэтому оба варианта можно устанавливать рядом; проверка
  обновлений выбирает ассет своего варианта. `scripts/build-android.sh` и
  workflow собирают полный и Lite `libbox` из одного дерева форка.

### Изменено

- Пресет «Жизнь в РФ»: добавлено правило **«Cloudflare через прокси»** — официальные
  IPv4/IPv6-диапазоны Cloudflare (`104.16.0.0/13`, `172.64.0.0/13`, `2606:4700::/32` и др.)
  уходят в прокси до `GeoIP: ru` и `GeoSite: category-ru`. Сайты за Cloudflare из РФ режутся
  после ~19 КБ, и раньше `.ru`-домены за CF попадали в DIRECT и не открывались.
  Прошлые конфиги с пресетом обновляются автоматически и остаются «Жизнью в РФ».
- Маршрутизация: правило `resolve` перед пользовательскими правилами — домены из
  mixed/socks теперь тоже проверяются IP-правилами (иначе Cloudflare → proxy работал
  только в TUN, а браузер через системный прокси уходил в DIRECT по `category-ru`).
- TUN: ядро теперь останавливается штатно через marker-файл (`PROTOGRID_SHUTDOWN_FILE`),
  поэтому sing-box сам закрывает TUN, а не оставляет Wintun-адаптер в состоянии удаления.
  Принудительное завершение осталось только запасным вариантом. Запуск больше не
  блокируется, если Windows всё ещё показывает старый интерфейс: приложение пробует
  запустить ядро, а при ошибке чистит Wintun-устройство и повторяет попытку. Перед
  запуском и после остановки зависшее устройство `protogrid_tun` дополнительно
  удаляется через `pnputil /remove-device`.
- Windows: ядро запускается в Job Object с `KILL_ON_JOB_CLOSE`, поэтому при аварийном
  завершении ProtoGrid не остаётся осиротевший `protogrid-core.exe`.
- Один экземпляр приложения на Windows, Linux и macOS: повторный запуск не создаёт
  второй процесс, а поднимает и фокусирует уже открытое окно — в том числе если оно
  свёрнуто или скрыто в трее. На Windows для этого используется именованный mutex и
  событие активации, на Linux/macOS — локальный Unix-сокет в каталоге приложения.

## [0.2.2] — 2026-11-26

### Добавлено

- **Обновления**: приложение само проверяет GitHub Releases при запуске и
  показывает доступную версию на «Обзоре» и в «Настройках → О приложении».
  Обновление скачивается по кнопке, с проверкой размера и SHA-256 из GitHub.
  В той же проверке участвуют sing-box и Xray-core: рядом с их версиями
  появляется доступная версия и кнопка «Обновить».
- **Android**: проверка новой версии APK на GitHub, скачивание с прогрессом,
  проверка SHA-256 и установка через системный установщик. Ядро
  ProtoGrid-core входит в APK и обновляется вместе с приложением.
- **Android**: подписки по HTTPS-ссылке — трафик, срок действия, ручное
  обновление и автообновление раз в 12 часов, серверы подписки в общем списке.
- **Android**: мониторинг делит трафик на «Всего / Прокси / Напрямую»; ядро
  отдаёт в Clash API суммы по каждому outbound, включая закрытые соединения.
- **Android**: вкладка «Настройки» — тихое уведомление, скорость в
  уведомлении, виджет на главном экране и плитка ProtoGrid в шторке; карточка
  обновлений переехала с «Обзора».
- **Android**: импорт OpenVPN-профиля `.ovpn` из файла.

### Изменено

- **Журнал**: префикс соединения от ядра (`[3441978519 0ms]`) больше не
  показывается в строках — это случайный ID соединения и время с его начала.
  В сохранённом файле лога префикс остаётся, чтобы вручную проследить одну связь.
- **Журнал**: строки, пришедшие через HTTP/SOCKS-вход (`inbound/mixed`),
  получили мягкую метку `IN`, чтобы пустая колонка «Маршрут» не выглядела
  ошибкой. Маршрут по-прежнему появляется на строке `outbound/...` того же
  соединения.

### Исправлено

- **Android**: при включённом VPN весь трафик падал с ошибкой ядра
  `no available network interface` — монитор default-сети отдавал ядру
  собственный интерфейс `tun0`; теперь запрашивается underlying-сеть с
  `NET_CAPABILITY_NOT_VPN`, а VPN-интерфейс исключён из списка исходящих.
- **Android**: удаление активного сервера перезапускает туннель на новом
  выбранном сервере, удаление последнего — автоматически отключает VPN.
- **Android**: запросы самого приложения (обновление подписки, проверка
  обновлений) больше не идут через собственный туннель.

## [0.2.1] — 2026-11-26

Публичная бета: безопасность, экспорт и импорт настроек, обновлённый бренд.

### Добавлено

- **Журнал**: у строк ядра появились метки `DIRECT`, `PROXY`, `BLOCK` и `TUN`
  с подсветкой (прямые соединения — янтарным, TUN — голубым), а в подвале
  считается, сколько записей ушло напрямую, через прокси и через TUN.
- **Настройки**: экспорт и импорт JSON с настройками, правилами и профилями
  маршрутизации. Файл не содержит серверов, UUID, паролей и токенов подписок;
  импорт не перезаписывает сохранённые серверы.

### Безопасность

- `config.json`, `runtime/*.json` и логи создаются с правами `0600`, папки
  профиля — `0700` (Unix). Раньше они оставались доступны на чтение другим
  пользователям системы.
- Ссылки подписок принимаются только по HTTPS; редиректы на `http://`
  блокируются. Ошибки загрузки больше не содержат URL с токеном, а ошибки
  разбора ссылок — исходную строку с UUID и паролем.
- Локальный Clash API получает случайный пароль на каждый запуск; без него
  `/connections` и `/proxies` недоступны другим процессам.
- Старые runtime-конфиги удаляются при смене ядра, отключении и после
  аварийного завершения, чтобы удалённые серверы не оставались на диске.
- Пароли, UUID и `xdrive_secrets` в форме сервера маскируются.
- Android: список профилей шифруется AES-GCM ключом из Android Keystore,
  старые plaintext-записи мигрируют при первом чтении.

### Исправлено

- Windows: TUN-интерфейс ProtoGrid называется `protogrid_tun` и больше не
  конфликтует с адаптером `singbox_tun` от v2rayN/Hiddify. После остановки ядра
  приложение ждёт, пока TUN-адаптер освободится, поэтому быстрый перезапуск
  больше не падает с `create adapter: ... file already exists`. Если адаптер
  всё же завис, в журнал пишется предупреждение с подсказкой.
- **Память**: журнал больше не раскладывает все 2000 строк при каждом кадре —
  список виртуализирован, и страница строит только видимые записи. На стенде
  открытие журнала с полной историей давало скачок ~54 МБ, теперь ~9 МБ.
  Строки ядра также перестали клонировать весь снимок состояния: журнал
  отдаётся странице через общий `Arc` и пересобирается только после новой
  записи.

## [0.2.0] — 2026-11-26

Публичная бета: нативный desktop-клиент и первый Android MVP.

### Добавлено

- **Android MVP**: отдельный клиент `apps/protogrid-android` (Kotlin/Compose,
  `VpnService`, ProtoGrid-core/`libbox`) и JNI-мост `crates/protogrid-mobile`
  к общему `protogrid-core`. Импорт share-ссылок, список серверов, подключение, foreground-уведомление,
  мониторинг трафика (график скорости за 60 секунд и счётчики из Clash API),
  per-app режимы («только выбранные» / «все кроме») и маршрутизация по трафику
  (пресеты, домены/IP/CIDR, GeoIP/GeoSite с локальным кэшем `.srs`); сборка APK для `arm64-v8a` в GitHub Actions по
  тегу `android-v*`.
- **Страница «Информация»**: нативное руководство со схемами подключения,
  сравнением ядер, описанием протоколов и транспортов, а также правилами
  выдачи прав для TUN на Windows, Linux и macOS.
- **Профили маршрутизации**: несколько собственных профилей вместо одного
  скрытого слота. Профили создаются, переименовываются и удаляются, активный
  хранится по id, а старый одиночный профиль автоматически переносится в список.

### Изменено

- Пресет «Обход РФ» переименован в «Жизнь в РФ»; старые конфиги мигрируют
  автоматически.
- Добавлен быстрый переход в «Информацию» по `Ctrl 8`.

### Исправлено

- Подписи карточек профилей маршрутизации больше не перехватывают клики.

## [0.1.2] — 2026-11-26

Первая публичная бета. Windows-сборка, Linux проверен на реальном подключении.

### Добавлено

- **OpenVPN**: импорт `ovpn://`/`openvpn://` и файлов `.ovpn`, TLS,
  `auth-user-pass`, `tls-auth`/`tls-crypt`/`tls-crypt-v2`, UDP и TCP через
  endpoint sing-box 1.14+ с тегом `with_openvpn`.
- **GeoIP/GeoSite**: кэш баз правил и флаги стран в списке серверов.
- **Интерфейс**: переработанный нативный лейаут — сайдбар, обзор с живыми
  графиками, карточки, таблица серверов, тёмная и светлая темы, поиск `Ctrl+K`,
  быстрые переходы `Ctrl 1…7`, бейджи протоколов.
- **Windows-пакеты**: установщик NSIS и портативный zip; `protogrid-core.exe` и
  `wintun.dll` лежат рядом с `ProtoGrid.exe`, а не внутри него.
- Лаунчеры `run-protogrid*.bat` и `run-portable*.bat`.

### Изменено

- Ядро `protogrid-core` вынесено в отдельный процесс и больше не встраивается в
  лончер: приложение стартует быстрее и не раздувается.
- Ядро ProtoGrid-core подхватывается рядом с приложением; стоковые
  sing-box и Xray-core скачиваются из настроек.
- Релизный профиль: `opt-level = "s"`, LTO, `codegen-units = 1`, `strip`.
- Установщик и портативный архив включают тексты лицензий: MIT, GPLv3 для ядра
  форка sing-box и GPLv2 для `wintun.dll`, плюс `THIRD_PARTY_NOTICES`.

### Исправлено

- Журнал дублировал префикс ядра в каждой строке.
- Портативный профиль больше не попадает в zip-архив.
